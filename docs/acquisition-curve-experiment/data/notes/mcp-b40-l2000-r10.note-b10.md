**Hand-off: enforce "no refresh token from client credentials" under the strict security profile**

**How the feature is wired.** Security profiles are an SPI (`server-spi-private/.../securityprofile/SecurityProfileProvider|ProviderFactory|Spi.java`), implemented by `services/.../securityprofile/DefaultSecurityProfileProvider(Factory).java`. The factory reads `<name>.json` from classpath/`conf`; `services/src/main/resources/strict-security-profile.json` names `client-profiles: keycloak-default-client-profiles` and `client-policies: keycloak-strict-client-policies`. In `keycloak-strict-client-policies.json` the policy "Openid-connect OAuth 2.1 confidential client" already carries the conditions `client-type=openid-connect` + `client-access-type=confidential` and applies the profile `oauth-2-1-for-confidential-client` (defined in `keycloak-default-client-profiles.json`). So the confidential/OIDC scoping comes free from the policy — put the rule in a client-policy **executor** and add it to that profile; do not re-check protocol/access type.

**What to write.** A new executor + factory in `services/src/main/java/org/keycloak/services/clientpolicy/executor/`. Imitate `RejectResourceOwnerPasswordCredentialsGrantExecutor(Factory)` for shape: `ClientPolicyExecutorProvider<Configuration>`, nested `Configuration extends ClientPolicyExecutorConfigurationRepresentation` with `@JsonProperty("auto-configure")`, `getProviderId()` returning the factory `PROVIDER_ID`, failure via `new ClientPolicyException(OAuthErrorException.INVALID_CLIENT_METADATA, ...)`. Imitate `ConsentRequiredExecutor` for the REGISTER/UPDATE split: on UPDATE use `ClientCRUDContext.getTargetClient()` alongside `getProposedClientRepresentation()` so an update that omits the flag is still rejected when the existing client has it on; auto-configure turns it off on create.

The flag is the client attribute `OIDCConfigAttributes.USE_REFRESH_TOKEN_FOR_CLIENT_CREDENTIALS_GRANT` (`client_credentials.use_refresh_token`); read/write it via `OIDCAdvancedConfigWrapper.isUseRefreshTokenForClientCredentialsGrant/set...`, or from the representation's attribute map (see `SecureClientUrisExecutor` for the null-safe map idiom).

**Easy to miss.** The executor factory almost certainly needs a `META-INF/services` provider registration in `services` (not verified here). Both admin REST and dynamic registration go through the same REGISTER/UPDATE events, so one executor covers both. Servers with no profile use `none-security-profile.json` and must stay unaffected.
