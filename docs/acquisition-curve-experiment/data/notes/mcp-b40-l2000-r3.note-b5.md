## Hand-off note: reject refresh tokens for client_credentials under `strict`

### Where things live
- Executors: `services/src/main/java/org/keycloak/services/clientpolicy/executor/` (each is `XExecutor` + `XExecutorFactory`, factory declaring a `PROVIDER_ID`).
- Every factory must be listed in `services/src/main/resources/META-INF/services/org.keycloak.services.clientpolicy.executor.ClientPolicyExecutorProviderFactory` or it will not load.
- `services/src/main/resources/strict-security-profile.json` only names two resource bundles: `keycloak-default-client-profiles` and `keycloak-strict-client-policies`. The strict policies file already binds the profile `oauth-2-1-for-confidential-client` to a policy conditioned on `client-type: openid-connect` + `client-access-type: confidential`, so the "confidential OIDC only / on by default" requirement is satisfied simply by adding the new executor to that profile's `executors` list in `keycloak-default-client-profiles.json`. Nothing needs to change for `lax`/`none`, and profiles carry no policies for servers with no security profile.
- Ignore `services/target/classes/*.json`: build output.

### What to imitate
`RejectImplicitGrantExecutor` and `HolderOfKeyEnforcerExecutor` are the closest models: `executeOnEvent` switches on `REGISTER`/`UPDATE`, casts to `ClientCRUDContext`, calls `autoConfigure(rep)` then `validate(rep)`, with a `Configuration extends ClientPolicyExecutorConfigurationRepresentation` holding `@JsonProperty("auto-configure")`. Sibling executors in the confidential OAuth 2.1 profile are configured `{"auto-configure": "true"}`; that is how a client created without mentioning the flag ends up with it off. Attribute access goes through `OIDCAdvancedConfigWrapper.fromClientRepresentation(rep)`. Failures are `ClientPolicyException(OAuthErrorException.INVALID_CLIENT_METADATA, ...)` (`FullScopeDisabledExecutor` uses `Errors.INVALID_REGISTRATION` instead) — this single path covers both admin REST and dynamic registration.

### The attribute
`OIDCConfigAttributes.USE_REFRESH_TOKEN_FOR_CLIENT_CREDENTIALS_GRANT = "client_credentials.use_refresh_token"` (`server-spi-private`). Whether `OIDCAdvancedConfigWrapper` exposes a typed getter for it was not checked.

### Easy to miss
- An UPDATE whose representation omits the attribute must still be rejected when the stored client has it on: consult `ClientCRUDContext.getTargetClient()` (returns null on REGISTER) as well as the proposed representation.
- Guard nulls in `validate` (`RejectImplicitGrantExecutor` unboxes unguarded; `FullScopeDisabledExecutor` null-checks).
