## Hand-off note

### Where the feature lives

Security profiles are shipped as resources in `services/src/main/resources/`: `strict-security-profile.json`, `lax-security-profile.json`, `none-security-profile.json`. Each is a thin descriptor naming two bundles, e.g. strict:

```json
{"name":"strict","client-profiles":"keycloak-default-client-profiles","client-policies":"keycloak-strict-client-policies"}
```

`keycloak-default-client-profiles.json` sits beside them; the `keycloak-strict-client-policies` bundle was not located in this record — find it before editing. Copies under `services/target/classes/` are build output; never edit them.

The profile machinery is `org.keycloak.securityprofile` (`SecurityProfileProvider`, `SecurityProfileProviderFactory`, `SecurityProfileSpi` in `server-spi-private`), implemented by `services/.../services/securityprofile/DefaultSecurityProfileProvider(Factory)`; `core/.../representations/idm/SecurityProfileConfiguration.java` is the representation.

Enforcement is the client-policy framework. Imitate an existing executor in `services/src/main/java/org/keycloak/services/clientpolicy/executor/` — `ConsentRequiredExecutor` and `FullScopeDisabledExecutor` look closest in shape (small, attribute-oriented); `SecureRequestObjectExecutor` also references security-profile concepts. SPI types you will need: `ClientPolicyContext`, `ClientPolicyEvent`, `ClientPolicyException` (`server-spi`), `ClientPolicyVote` (`server-spi-private`). `services/.../clientpolicy/ClientPoliciesUtil.java` is where profile/policy JSON is loaded and is likely the place a new executor must be registered/known.

### Change shape and dependencies

1. New executor (plus its factory, and a provider-registration entry alongside the other executor factories) that rejects the refresh-token-from-client-credentials switch for confidential OIDC clients, and normalises it to off when absent on create.
2. Add the executor to the strict client-policies bundle only — lax and none must stay byte-identical in behaviour.

Order matters: the executor must exist before the bundle can reference it by provider id.

### Easy to miss

- The exact client switch/attribute name is not established by this record; confirm it from the client representation before coding.
- Both admin REST and dynamic registration flow through client-policy events — cover create *and* update events, and on update fall back to the stored client when the request omits the switch.
- Executors must only vote/act for confidential clients using the OIDC protocol.
