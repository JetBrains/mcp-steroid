## Hand-off note: forbid refresh tokens on client credentials grant under the `strict` security profile

**Where the feature lives.** Built-in security profiles are JSON resources in `services/src/main/resources`: `strict-security-profile.json`, `lax-security-profile.json`, `none-security-profile.json`. Each names a client-profiles set (all three use `keycloak-default-client-profiles`) and a client-policies set (`keycloak-strict-client-policies.json`, `keycloak-lax-client-policies.json`, `null` for `none`). They are loaded by `services/src/main/java/org/keycloak/services/securityprofile/DefaultSecurityProfileProvider(+Factory)` against the SPI in `server-spi-private/.../securityprofile`.

**The hook to use.** `keycloak-strict-client-policies.json` already contains a policy “Openid-connect OAuth 2.1 confidential client” whose conditions are `client-type: openid-connect` plus `client-access-type: confidential`, and which applies the client profile `oauth-2-1-for-confidential-client`. That profile lives in the `keycloak-default-client-profiles` resource (not inspected — read it first). Adding a new executor to that profile gives you the confidential/OIDC scoping and the “only under strict / unchanged without a profile” requirements for free.

**What to add.** A client-policy executor plus its factory in `services/src/main/java/org/keycloak/services/clientpolicy/executor/`, modelled on the existing Executor/ExecutorFactory pairs there (e.g. `FullScopeDisabledExecutor(Factory)`, `RegistrationAccessTokenRotationDisabledExecutorFactory`). It must reject client create and update events (admin REST and dynamic client registration, the latter via `AbstractClientRegistrationProvider`) and, on an update whose payload omits the attribute, consult the stored client. The attribute is `OIDCConfigAttributes.USE_REFRESH_TOKEN_FOR_CLIENT_CREDENTIALS_GRANT` (`client_credentials.use_refresh_token`, `server-spi-private`); read/write it through `OIDCAdvancedConfigWrapper` (`services/.../protocol/oidc`), which already defaults it to `false`.

**Easy to miss.** Factory registration (service-loader file) — check how a sibling factory is registered. Do not touch `lax`/`none` policy JSON. `services/.../managers/GrantTypeEndpointRestrictionValidator` may overlap; check before duplicating logic.

**Verify.** Unit test beside `SecureRedirectUrisEnforcerExecutorTest`; profile-loading tests in `services/src/test/.../securityprofile`; end-to-end coverage under `testsuite/integration-arquillian/tests/base`.
