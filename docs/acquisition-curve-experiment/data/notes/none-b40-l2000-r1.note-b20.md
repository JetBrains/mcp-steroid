**Hand-off note: forbid refresh tokens for the client-credentials grant under the `strict` security profile**

**Where the machinery lives**
- Profiles: `services/src/main/resources/{none,strict,lax}-security-profile.json`; each names a client-profiles and a client-policies resource in the same directory (`keycloak-default-client-profiles.json`, `keycloak-strict-client-policies.json`, `keycloak-lax-client-policies.json`).
- `keycloak-strict-client-policies.json` already has policy "Openid-connect OAuth 2.1 confidential client" (conditions `client-type: openid-connect` + `client-access-type: confidential`) bound to profile `oauth-2-1-for-confidential-client`, which is defined inside `keycloak-default-client-profiles.json` (large file, not fully reviewed). Adding an executor to that profile gives you "confidential OIDC only", "on by default under strict", and "no effect without a profile" for free.
- Executors: `services/src/main/java/org/keycloak/services/clientpolicy/executor/`, always a pair `XExecutor` + `XExecutorFactory` with `public static final String PROVIDER_ID`. **The factory must be listed in** `services/src/main/resources/META-INF/services/org.keycloak.services.clientpolicy.executor.ClientPolicyExecutorProviderFactory`.

**What to write**
Model on `RejectResourceOwnerPasswordCredentialsGrantExecutor`: handle `REGISTER` and `UPDATE`, cast to `ClientCRUDContext`, read `getProposedClientRepresentation()`, and on violation throw `ClientPolicyException(OAuthErrorException.INVALID_CLIENT_METADATA, "...")`. Both admin-REST and dynamic-registration contexts implement `ClientCRUDContext`, so one handler covers both. Read the flag via `OIDCAdvancedConfigWrapper.fromClientRepresentation(rep).isUseRefreshTokenForClientCredentialsGrant()` (see `HolderOfKeyEnforcerExecutor` for this style); the attribute is `OIDCConfigAttributes.USE_REFRESH_TOKEN_FOR_CLIENT_CREDENTIALS_GRANT` (`client_credentials.use_refresh_token`) and the wrapper defaults it to `false`, which is why a client created without mentioning it needs no auto-configuration.

**Easy to miss**
An update payload that omits the attribute: the proposed representation alone is not enough. `ClientCRUDContext.getTargetClient()` returns the existing `ClientModel` (null on REGISTER) — check it too, via `OIDCAdvancedConfigWrapper.fromClientModel`. (`SamlSignatureEnforcerExecutor` shows the alternative post-event style using `REGISTERED`/`UPDATED` with `AdminClientRegisteredContext`/`AdminClientUpdatedContext`.)
