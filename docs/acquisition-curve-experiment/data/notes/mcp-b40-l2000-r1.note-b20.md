## Hand-off note: enforce "no refresh token from client credentials grant" under the strict security profile

### What to imitate
The mechanism is a **client policy executor**. Closest templates, both in `services/src/main/java/org/keycloak/services/clientpolicy/executor/`:
- `RejectResourceOwnerPasswordCredentialsGrantExecutor` (+ `...Factory`) — reject-on-REGISTER/UPDATE plus grant-time rejection, `auto-configure` config property.
- `ConsentRequiredExecutor` — the UPDATE case: it distinguishes `getProposedClientRepresentation()` from `getTargetClient()` when the flag is absent from the proposed representation. Your requirement is the opposite of its leniency: absent-in-request + already-on-in-target must **fail**.

The flag is `OIDCConfigAttributes.USE_REFRESH_TOKEN_FOR_CLIENT_CREDENTIALS_GRANT` (`"client_credentials.use_refresh_token"`), read/written via `OIDCAdvancedConfigWrapper.isUseRefreshTokenForClientCredentialsGrant()/set...` (defaults to `false` when the attribute is missing).

### Change graph
1. New executor + factory in the package above; the factory's `PROVIDER_ID` string is what JSON refers to.
2. Register the factory class in `services/src/main/resources/META-INF/services/org.keycloak.services.clientpolicy.executor.ClientPolicyExecutorProviderFactory` — omitting this makes the profile JSON unloadable.
3. Add the executor to a global profile in `services/src/main/resources/keycloak-default-client-profiles.json`. `strict-security-profile.json` names `keycloak-default-client-profiles` + `keycloak-strict-client-policies`; the strict policies file (contents not inspected here) references `oauth-2-1-for-confidential-client`, which is the natural home given the confidential-OIDC-only requirement.

### Easy to miss
- Admin REST and dynamic registration both arrive as REGISTER/UPDATE `ClientCRUDContext` (`AdminClientRegisterContext`, `DynamicClientRegisterContext`, and the Update variants), so one executor covers both.
- Profiles referenced by `lax-security-profile.json` / `none-security-profile.json` must stay untouched so no-profile behaviour is unchanged.
- `js/apps/admin-ui/src/context/server-info/__tests__/mock.json` lists executor ids.
