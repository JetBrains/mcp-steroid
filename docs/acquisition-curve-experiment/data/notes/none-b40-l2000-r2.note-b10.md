**Hand-off note: forbid refresh tokens for client_credentials under the `strict` security profile**

**The mechanism to build on.** Security profiles are an internal SPI (`server-spi-private/.../securityprofile/`: `SecurityProfileSpi`, `SecurityProfileProvider`, `SecurityProfileProviderFactory`), implemented by `services/.../services/securityprofile/DefaultSecurityProfileProvider(+Factory)`. A profile only supplies default *client profiles* and *client policies* (`getDefaultClientProfiles()` / `getDefaultClientPolicies()`), so the new rule must be expressed as a client-policy executor, not as ad-hoc validation code.

Profiles are declared by small JSON files in `services/src/main/resources`: `strict-security-profile.json` (`{"name":"strict","client-profiles":"keycloak-default-client-profiles","client-policies":"keycloak-strict-client-policies"}`), plus `lax-` and `none-` (the latter has `"client-policies":null`, which is why a server with no profile must stay unaffected). The matching `keycloak-default-client-profiles.json` lives beside them; the strict policies resource was not inspected — locate it before editing. Note `services/target/classes/**` holds build copies; edit only `src/main/resources`.

**What to change.** (1) Add an executor under `services/src/main/java/org/keycloak/services/clientpolicy/executor/` plus its factory, imitating existing ones there (`ConsentRequiredExecutor`, `FullScopeDisabledExecutor`, `SecureRequestObjectExecutor`); register the factory the same way they are. It must reject on client register and client update events (see `ClientPolicyEvent`, `ClientPolicyContext`, `ClientPolicyException` in `server-spi`) so both admin REST and dynamic registration are covered. (2) Add the executor to the strict client-profile/policy JSON so it is active out of the box.

**Easy to miss.** The flag is `OIDCConfigAttributes.USE_REFRESH_TOKEN_FOR_CLIENT_CREDENTIALS_GRANT` = `client_credentials.use_refresh_token` (`server-spi-private`), read/written via `OIDCAdvancedConfigWrapper` with default `"false"` — that default already satisfies "created without mentioning it ends up off". For an update whose representation omits the attribute you must consult the *stored* client, otherwise the already-enabled case slips through. Restrict the check to confidential OIDC clients (skip public and non-OIDC protocols).

**Verification.** Mirror `tests/base/src/test/java/org/keycloak/tests/securityprofile/LaxSecurityProfileTest.java` for the strict profile; `services/src/test/.../DefaultSecurityProfileProverFactoryTest.java` covers profile loading, and `testsuite/.../client/policies/AbstractClientPoliciesTest.java` is the older policy-test base. Cover create, update, omitted-attribute update, default-off, and no-profile-unchanged.
