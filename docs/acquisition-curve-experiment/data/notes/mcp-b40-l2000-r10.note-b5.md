**Hand-off note: reject refresh tokens for client_credentials under the `strict` security profile**

**Where the feature lives**
- SPI: `server-spi-private/src/main/java/org/keycloak/securityprofile/` — `SecurityProfileProvider` (exposes `getName()`, `getDefaultClientProfiles()`, `getDefaultClientPolicies()`), its factory and `SecurityProfileSpi`.
- Implementation: `services/src/main/java/org/keycloak/services/securityprofile/DefaultSecurityProfileProvider{,Factory}.java`. The factory reads `<name>.json` from classpath or the `conf` folder (`name` option, default `none-security-profile`) into `org.keycloak.representations.idm.SecurityProfileConfiguration`, then validates its referenced profiles/policies through `ClientPoliciesUtil.readGlobalClientProfilesRepresentation/readGlobalClientPoliciesRepresentation`.
- Profile resources, all in `services/src/main/resources/`: `strict-security-profile.json`, `lax-…`, `none-…`, plus `keycloak-default-client-profiles.json`, `keycloak-strict-client-policies.json`, `keycloak-lax-client-policies.json`. `strict-security-profile.json` points at `keycloak-default-client-profiles` + `keycloak-strict-client-policies`; the strict policy “Openid-connect OAuth 2.1 confidential client” already matches conditions `client-type=openid-connect` and `client-access-type=confidential` and applies the client profile **`oauth-2-1-for-confidential-client`** — that profile (in `keycloak-default-client-profiles.json`) is where the new executor belongs, so no policy/condition work should be needed.

**What to add**
A new client-policy executor in `services/src/main/java/org/keycloak/services/clientpolicy/executor/`, modelled closely on `RejectResourceOwnerPasswordCredentialsGrantExecutor` and its `…Factory`: provider + factory pair, nested `Configuration extends ClientPolicyExecutorConfigurationRepresentation` with an `@JsonProperty("auto-configure")` flag, `executeOnEvent` handling `REGISTER`/`UPDATE` by casting to `ClientCRUDContext`, calling auto-configure (force the flag off) then validate, and failing with `ClientPolicyException(OAuthErrorException.INVALID_CLIENT_METADATA, …)`. This single path covers both the admin REST API and dynamic client registration. Register the factory the same way the ROPC factory is registered, and add the executor to `oauth-2-1-for-confidential-client`.

**Easy to miss**
- The ROPC template validates only `getProposedClientRepresentation()` and dereferences the boolean unconditionally; an update that omits the setting must still be rejected when the stored client has it on, so consult the existing client too and treat null as “unchanged”, not “false”.
- The exact client attribute/representation field for “refresh token from client credentials” is not established by this record; confirm it before coding.
- Behaviour must be unchanged under `none-security-profile`.

Integration coverage lives in `tests/base/src/test/java/org/keycloak/tests/securityprofile/` — `LaxSecurityProfileTest` is the pattern to imitate for a strict-profile test asserting create/update rejection and the default-off case.
