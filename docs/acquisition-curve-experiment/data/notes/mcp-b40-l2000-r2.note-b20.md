**Hand-off note — enforce "no refresh token from client credentials grant" under the `strict` security profile**

**Where the feature lives.** Security profiles are JSON files in `services/src/main/resources`: `none-/lax-/strict-security-profile.json`, each naming a client-profiles file (`keycloak-default-client-profiles.json`) and a client-policies file (`keycloak-strict-client-policies.json`, `keycloak-lax-client-policies.json`; `none` has null policies). Loaded by `services/.../securityprofile/DefaultSecurityProfileProviderFactory` (option `name`, default `none-security-profile`). In the strict policies, confidential OIDC clients are matched by conditions `client-type: openid-connect` + `client-access-type: confidential` and mapped to the profile `oauth-2-1-for-confidential-client`, defined in `keycloak-default-client-profiles.json`.

**What to add.** A new client-policy executor pair under `services/src/main/java/org/keycloak/services/clientpolicy/executor/`, then reference its provider id from the `oauth-2-1-for-confidential-client` profile. Closest models:
- `RejectResourceOwnerPasswordCredentialsGrantExecutor` — REGISTER/UPDATE handling, `auto-configure` flag, `validate` throwing `ClientPolicyException(OAuthErrorException.INVALID_CLIENT_METADATA, ...)`.
- `ConsentRequiredExecutor` — on UPDATE it also consults `ClientCRUDContext.getTargetClient()`, which is how you catch an update whose payload omits the flag while the stored client has it on (`getProposedClientRepresentation()` alone is not enough).
- `SecureLogoutExecutor`/`SecureLogoutExecutorFactory` — attribute-based check via `OIDCAdvancedConfigWrapper.fromClientRepresentation(...)`, plus factory boilerplate (`PROVIDER_ID`, `ProviderConfigProperty`, `getHelpText`).

The flag is `OIDCConfigAttributes.USE_REFRESH_TOKEN_FOR_CLIENT_CREDENTIALS_GRANT` (`client_credentials.use_refresh_token`); use `OIDCAdvancedConfigWrapper.isUseRefreshTokenForClientCredentialsGrant()` / setter (`fromClientModel` for the target client), whose default is already `false`.

**Easy to miss.**
- Register the factory FQCN in `services/src/main/resources/META-INF/services/org.keycloak.services.clientpolicy.executor.ClientPolicyExecutorProviderFactory`.
- `oauth-2-1-for-confidential-client` is shared by the **lax** policies too; if the rule must be strict-only, do not simply extend that profile.
- Admin REST and dynamic registration both arrive as REGISTER/UPDATE `ClientCRUDContext` (`Admin*`/`Dynamic*ClientRegisterContext`, `*UpdateContext`), so one executor covers both.
- Avoid unguarded unboxing of representation booleans (the ROPC executor does this).
- `js/apps/admin-ui/src/context/server-info/__tests__/mock.json` enumerates executor ids.

**Verify.** `services/src/test/.../DefaultSecurityProfileProverFactoryTest` parses none/lax/strict files. Integration test style: `tests/base/.../securityprofile/LaxSecurityProfileTest` (`@KeycloakIntegrationTest` with a `KeycloakServerConfig` selecting the profile) — no strict counterpart exists yet. Per-restriction assertions modelled on `testsuite/.../client/OAuth2_1ConfidentialClientTest`.
