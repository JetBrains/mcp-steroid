## Hand-off note: enforce "no refresh token from client credentials grant" under the `strict` security profile

### Where the feature lives
- Security profile SPI: `server-spi-private/src/main/java/org/keycloak/securityprofile/` (`SecurityProfileSpi`, `SecurityProfileProvider`, `SecurityProfileProviderFactory`); implementation `services/src/main/java/org/keycloak/services/securityprofile/DefaultSecurityProfileProvider(Factory).java`, registered in `services/src/main/resources/META-INF/services/org.keycloak.securityprofile.SecurityProfileProviderFactory`. Representation: `core/src/main/java/org/keycloak/representations/idm/SecurityProfileConfiguration.java`.
- Shipped profiles: `services/src/main/resources/{strict,lax,none}-security-profile.json`. `strict-security-profile.json` is only three keys: `name`, `client-profiles` → `keycloak-default-client-profiles`, `client-policies` → `keycloak-strict-client-policies`; both resolve to same-named `.json` files in `services/src/main/resources/`.
- Client profiles JSON entries are `{"executor": "<id>", "configuration": {...}}` (e.g. `reject-implicit-grant` with `auto-configure`), grouped into named profiles such as `fapi-2-security-profile`.

### What to change, in order
1. Add a new executor + factory in `services/src/main/java/org/keycloak/services/clientpolicy/executor/`, imitating the pair `RejectImplicitGrantExecutor` / `RejectImplicitGrantExecutorFactory` (also compare `RejectResourceOwnerPasswordCredentialsGrantExecutor*`, `RejectRequestExecutor*`); the factory interface is `server-spi-private/.../services/clientpolicy/executor/ClientPolicyExecutorProviderFactory.java`.
2. Register the factory in `services/src/main/resources/META-INF/services/org.keycloak.services.clientpolicy.executor.ClientPolicyExecutorProviderFactory`.
3. Wire the executor into the client profile(s) that `keycloak-strict-client-policies.json` selects, so it is active out of the box under `strict` and inert with no profile.

### Easy to miss
- Both admin-REST create/update and dynamic client registration must be covered; which client-policy contexts the existing Reject* executors handle was not inspected — check before assuming.
- Update-without-the-field must still fail, so the executor has to fall back to the stored client's current value, and create-without-the-field must yield the feature off.
- Content of `keycloak-strict-client-policies.json` was not read.
