# Hand-off: reject refresh tokens for client credentials grant under `strict`

## Goal
A new client-policy executor that, on client REGISTER/UPDATE, rejects a confidential OIDC client whose `client_credentials.use_refresh_token` switch is on, and defaults it to off. Wire it into the OAuth 2.1 confidential-client profile so `strict` enforces it out of the box.

## What to imitate
All in `services/src/main/java/org/keycloak/services/clientpolicy/executor/`:
- `HolderOfKeyEnforcerExecutor` is the closest model: it holds a `KeycloakSession`, an inner `Configuration extends ClientPolicyExecutorConfigurationRepresentation` with a `@JsonProperty("auto-configure") Boolean autoConfigure`, and on `REGISTER`/`UPDATE` casts the context to `ClientCRUDContext`, calls `autoConfigure(...)` then `validate(...)` on `getProposedClientRepresentation()`, using `OIDCAdvancedConfigWrapper.fromClientRepresentation(rep)` for the attribute. `RejectImplicitGrantExecutor` and `FullScopeDisabledExecutor` are the same shape (note the differing errors: `OAuthErrorException.INVALID_CLIENT_METADATA` vs `Errors.INVALID_REGISTRATION`).
- The attribute constant is `OIDCConfigAttributes.USE_REFRESH_TOKEN_FOR_CLIENT_CREDENTIALS_GRANT` (`server-spi-private`); the wrapper accessors are `isUseRefreshTokenForClientCredentialsGrant()` / `setUseRefreshTokenForClientCredentialsGrant(boolean)`.
- Every executor needs a `...Factory` (with a `PROVIDER_ID` returned by `getProviderId()`) — copy `FullScopeDisabledExecutorFactory`.

## Changes and their dependencies
1. New executor + factory as above.
2. Register the factory class in `services/src/main/resources/META-INF/services/org.keycloak.services.clientpolicy.executor.ClientPolicyExecutorProviderFactory` — without this the profile JSON cannot resolve it.
3. Add the executor (likely `"auto-configure": "true"`) to the `oauth-2-1-for-confidential-client` profile in `services/src/main/resources/keycloak-default-client-profiles.json`. `keycloak-strict-client-policies.json` already binds that profile to a policy conditioned on protocol `openid-connect` + access type `confidential`, and `strict-security-profile.json` already references both files, so no policy/profile-set edits are needed; confidential-only and OIDC-only scoping comes for free. `keycloak-lax-client-policies.json` also mentions the profile — check the effect there.

## Easy to miss
- An UPDATE whose representation omits the attribute: the proposed rep alone is not enough, so consult the stored client. Precedents for `ClientCRUDContext.getTargetClient()` (null on REGISTER) are `ConsentRequiredExecutor`, `ClientSecretRotationExecutor`, `TlsClientAuthCASubjectDNExecutor`.
- Both admin REST API and dynamic client registration go through the same REGISTER/UPDATE contexts, so one executor covers both.
- Resources are duplicated under `services/target/classes/` — edit only `src/main/resources`.
