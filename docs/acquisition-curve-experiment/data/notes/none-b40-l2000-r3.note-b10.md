## Hand-off note: forbid refresh tokens for client credentials under the `strict` security profile

### Where the pieces live
- **Security profiles** are plain JSON in `services/src/main/resources/{strict,lax,none}-security-profile.json`. `strict` is only three lines: a name plus `"client-profiles":"keycloak-default-client-profiles"` and `"client-policies":"keycloak-strict-client-policies"`. Those two identifiers name the profile/policy sets that must contain the new rule; where those sets are defined was not established — find them before anything else. Ignore the identical copies under `services/target/classes` (build output).
- The profile is loaded by `SecurityProfileConfiguration` (core, `representations/idm`), `DefaultSecurityProfileProvider(Factory)` (`services/.../services/securityprofile`) and the SPI in `server-spi-private/.../securityprofile`, registered via `META-INF/services/org.keycloak.securityprofile.SecurityProfileProviderFactory`. The provider only exposes default client profiles/policies, so enforcement must be expressed as a **client policy executor**, not as new provider API.
- **Executors to imitate**: `services/src/main/java/org/keycloak/services/clientpolicy/executor/`, always an `XExecutor` + `XExecutorFactory` pair. Closest analogues by intent: `ConfidentialClientAcceptExecutor`, `RejectResourceOwnerPasswordCredentialsGrantExecutor`, `SuppressRefreshTokenRotationExecutor*`, `RegistrationAccessTokenRotationDisabledExecutor`. Contracts: `ClientPolicyExecutorProvider(Factory)` in `server-spi-private`, `ClientPolicyContext`/`ClientPolicyEvent`/`ClientPolicyException` in `server-spi`.

### The switch in question
`OIDCConfigAttributes.USE_REFRESH_TOKEN_FOR_CLIENT_CREDENTIALS_GRANT` = `"client_credentials.use_refresh_token"` (`server-spi-private/.../protocol/oidc`), read through `OIDCAdvancedConfigWrapper` where the default is already `"false"`.

### Dependencies and pitfalls
- One executor must cover admin-REST create/update **and** dynamic registration — that is the set of client-policy events it subscribes to; enumerate `ClientPolicyEvent` before choosing.
- An update representation may omit the attribute; fall back to the stored client, hence read via the wrapper, not the request only.
- Restrict to confidential OIDC clients, and register the new factory (executor SPI service file) or `strict` will silently not apply it.
