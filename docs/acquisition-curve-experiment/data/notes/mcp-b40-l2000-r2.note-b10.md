**Hand-off note: reject refresh tokens for the client-credentials grant under the `strict` security profile**

**Shape of the feature.** Security profiles are JSON resources in `services/src/main/resources` (`strict-security-profile.json`, `lax-…`, `none-…`); `strict` names `keycloak-default-client-profiles` (client profiles) and `keycloak-strict-client-policies`. The strict policies file already contains a policy "Openid-connect OAuth 2.1 confidential client" (conditions `client-type`=openid-connect + `client-access-type`=confidential) that applies the client profile `oauth-2-1-for-confidential-client`, defined in `keycloak-default-client-profiles.json`. So the confidential/OIDC scoping is already done: the change is a new client-policy executor added to that profile's `executors` list. No admin configuration and no extra wiring for the two entry points — client-policy `REGISTER`/`UPDATE` events already cover both the admin REST API and dynamic client registration (see `ClientCRUDContext` javadoc).

**What to write.** A new executor + factory in `services/src/main/java/org/keycloak/services/clientpolicy/executor/`, registered in `services/src/main/resources/META-INF/services/org.keycloak.services.clientpolicy.executor.ClientPolicyExecutorProviderFactory`.
- Overall skeleton and error style: `RejectResourceOwnerPasswordCredentialsGrantExecutor` (auto-configure + validate on REGISTER/UPDATE, `ClientPolicyException(OAuthErrorException.INVALID_CLIENT_METADATA, …)`).
- Factory boilerplate (`PROVIDER_ID`, `getHelpText`, `ProviderConfigProperty`): `SecureLogoutExecutorFactory`.
- Reading the flag from a proposed representation: `OIDCAdvancedConfigWrapper.fromClientRepresentation(rep)` (as in `SecureLogoutExecutor`), attribute `OIDCConfigAttributes.USE_REFRESH_TOKEN_FOR_CLIENT_CREDENTIALS_GRANT` = `client_credentials.use_refresh_token`, accessors `isUseRefreshTokenForClientCredentialsGrant` / `setUseRefreshTokenForClientCredentialsGrant`.
- **Easy to miss:** an UPDATE whose payload omits the attribute must still fail if the stored client has it on — consult `ClientCRUDContext.getTargetClient()` on UPDATE, as `ConsentRequiredExecutor` does. And "created without mentioning it ends up off" needs an auto-configure step writing `false`.
