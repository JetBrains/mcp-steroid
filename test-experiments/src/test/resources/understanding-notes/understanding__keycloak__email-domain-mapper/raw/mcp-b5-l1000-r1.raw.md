Keycloak. Mapper goes in `services/src/main/java/org/keycloak/protocol/oidc/mappers/` (module `services`).

Extend `AbstractOIDCProtocolMapper` and implement the marker interfaces `OIDCIDTokenMapper, OIDCAccessTokenMapper, UserInfoTokenMapper, TokenIntrospectionTokenMapper` (all in that package). The base class already reads the INCLUDE_IN_ID_TOKEN/ACCESS_TOKEN/USERINFO/INTROSPECTION config in its transform* methods and then calls `setClaim(IDToken, ProtocolMapperModel, UserSessionModel, KeycloakSession, ClientSessionContext)` — override only that; don't touch transform*. Read `token.getEmail()`, bail on null / no '@', else put the suffix into `token.getOtherClaims()`.

Config: static `List<ProviderConfigProperty>` via `OIDCAttributeMapperHelper.addIncludeInTokensConfig(...)`; `getDisplayCategory()` = OIDCAttributeMapperHelper's TOKEN_MAPPER_CATEGORY; `getId()` = `oidc-email-domain-mapper`. Imitate `HardcodedClaim`/`AcrProtocolMapper`.

Two registrations, easy to forget (I could not verify these — check both): the `META-INF/services/org.keycloak.protocol.ProtocolMapper` file under `services/src/main/resources`, and the built-in list in `OIDCLoginProtocolFactory` (`builtins` map / `getBuiltinMappers()`), which usually needs a static `create(...)` returning a `ProtocolMapperModel`. Grep for tests asserting builtin-mapper counts.
