All in module `services`. Clone `org/keycloak/protocol/oidc/mappers/FullNameMapper.java` — it is the exact pattern: extend `AbstractOIDCProtocolMapper`, implement `OIDCAccessTokenMapper, OIDCIDTokenMapper, UserInfoTokenMapper, TokenIntrospectionTokenMapper` (these interfaces are what the include-in-X admin switches key off), static block calling `OIDCAttributeMapperHelper.addIncludeInTokensConfig(configProperties, X.class)`, `getDisplayCategory()` = `TOKEN_MAPPER_CATEGORY`, override `setClaim(IDToken, ProtocolMapperModel, UserSessionModel)` and put `email_domain` in `token.getOtherClaims()` only for a non-empty part after '@'.

Read the email off the token. `IDToken.getEmail()` may be null: the builtin "email" mapper writes into `getOtherClaims()` ("email" is absent from OIDCAttributeMapperHelper's tokenPropertySetters) — check both (I'm unsure which wins). Mappers are sorted by `ProtocolMapper.getPriority()` (default 0) in `ProtocolMapperUtils`; override it > 0 to run after the email mapper.

Two registrations, both needed: add the FQCN to `services/src/main/resources/META-INF/services/org.keycloak.protocol.ProtocolMapper` (resolves `oidc-email-domain-mapper`), and add a static `create(...)` plus `builtins.put(NAME, model)` in `OIDCLoginProtocolFactory` (field `builtins` ~l.190) — that map is what `getBuiltinMappers()` exposes through ServerInfoAdminResource to the console's builtin-mapper list.

Do NOT edit `createDefaultClientScopesImpl`: export/import tests (ExportImportUtil, partialexport-testrealm.json) assert exact default-scope mapper sets.
