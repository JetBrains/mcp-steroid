Keycloak. All work is in the `services` module, package `org.keycloak.protocol.oidc.mappers`.

**Template to copy:** `AcrProtocolMapper.java` in that package is the closest small example — static `List<ProviderConfigProperty> configProperties` filled in a static block by `OIDCAttributeMapperHelper.addIncludeInTokensConfig(configProperties, YourMapper.class)`, `PROVIDER_ID`, `getId/getDisplayType/getHelpText`, `getDisplayCategory()` returning `TOKEN_MAPPER_CATEGORY` (constant on `AbstractOIDCProtocolMapper`), an override of `setClaim(IDToken, ProtocolMapperModel, UserSessionModel, KeycloakSession, ClientSessionContext)`, and a static `create(...)` returning a `ProtocolMapperModel` with the INCLUDE_IN_* config keys.

Extend `AbstractOIDCProtocolMapper` and implement `OIDCIDTokenMapper, OIDCAccessTokenMapper, UserInfoTokenMapper, TokenIntrospectionTokenMapper`. Those marker interfaces are what `addIncludeInTokensConfig` inspects to emit the admin switches, and the base class's `transformIDToken/transformAccessToken/transformUserInfoToken/transformIntrospectionToken` already gate on them — do not override the transform methods.

In `setClaim`: read `token.getEmail()` (`core/.../representations/IDToken.java`), bail out on null / no `@`, else `token.getOtherClaims().put("email_domain", <substring after last @>)`.

**Two registrations, both required and easy to forget:**
1. Append the FQCN to `services/src/main/resources/META-INF/services/org.keycloak.protocol.ProtocolMapper` — this is what makes `oidc-email-domain-mapper` resolvable.
2. `OIDCLoginProtocolFactory.initBuiltIns()` (services/.../protocol/oidc/OIDCLoginProtocolFactory.java, ~line 192): add a display-name constant and `builtins.put(...)`. `getBuiltinMappers()` is surfaced to the admin console by `ServerInfoAdminResource` (~line 383) — that is the "ships with" list. Do **not** also add it to a default client scope in `createDefaultClientScopes`; that would alter tokens in every realm.

**Uncertain/watch:** the `email` claim is itself produced by the builtin `UserAttributeMapper`; mapper execution order follows `ProtocolMapper.getPriority()` (defaults 0; constants in `ProtocolMapperUtils`, higher = later). If `token.getEmail()` comes back null at userinfo/access-token time, override `getPriority()` to run late.

**Verify:** don't run the reactor. Pattern tests: `testsuite/integration-arquillian/tests/base/src/test/java/org/keycloak/testsuite/oauth/OIDCProtocolMappersTest.java` (classic) and `tests/base/src/test/java/org/keycloak/tests/admin/client/{AbstractProtocolMapperTest,ClientProtocolMapperTest}.java` (new framework).

Leave `AbstractOIDCProtocolMapper`, `OIDCAttributeMapperHelper` and existing builtins untouched.
