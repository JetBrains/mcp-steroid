**Where.** All OIDC mappers live in `services/src/main/java/org/keycloak/protocol/oidc/mappers/`. **Copy `HardcodedClaim.java` as your template** — verified shape:
`public class X extends AbstractOIDCProtocolMapper implements OIDCAccessTokenMapper, OIDCIDTokenMapper, UserInfoTokenMapper, TokenIntrospectionTokenMapper`, a `public static final String PROVIDER_ID`, a `static {}` block filling a `List<ProviderConfigProperty> configProperties` via `OIDCAttributeMapperHelper.addIncludeInTokensConfig(configProperties, X.class)` (this alone creates the four admin switches; the base class enforces them, you don't check them), and overrides `getId/getDisplayType/getDisplayCategory (returns TOKEN_MAPPER_CATEGORY)/getHelpText/getConfigProperties`. Only override the `setClaim(IDToken token, ProtocolMapperModel, UserSessionModel, ...)` hook — read the real signature off `AbstractOIDCProtocolMapper` (there is a legacy 3-arg and a wider one with `KeycloakSession`/`ClientSessionContext`); userinfo/introspection route through the same hook. `AudienceProtocolMapper` and `SubMapper` are secondary examples.

**Logic.** `token.getEmail()`; if null or no `@`, return without touching the token. Since the claim name is fixed, do NOT call `OIDCAttributeMapperHelper.mapClaim(...)` unless you also add `addTokenClaimNameConfig` — mapClaim reads `TOKEN_CLAIM_NAME` from config and will NPE otherwise. Writing `token.getOtherClaims().put("email_domain", domain)` is the safe route (check mapClaim first).

**Ordering trap.** `email` is put on the token by the built-in email mapper (a `UserPropertyMapper`). If yours runs first, `getEmail()` is null. `SubMapper` shows the escape hatch: `@Override getPriority()` returning a `ProtocolMapperUtils` constant. Check ordering explicitly.
