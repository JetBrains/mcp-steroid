This is Keycloak. Everything happens in the `services` module.

**What to create.** `services/src/main/java/org/keycloak/protocol/oidc/mappers/EmailDomainMapper.java` (name free). Copy the shape of `HardcodedClaim.java` in that same package — it is the closest template (also look at `ClaimsParameterTokenMapper`, `AmrProtocolMapper`, both there). Pattern: `extends AbstractOIDCProtocolMapper implements OIDCIDTokenMapper, OIDCAccessTokenMapper, UserInfoTokenMapper, TokenIntrospectionTokenMapper`, a `public static final String PROVIDER_ID = "oidc-email-domain-mapper"`, a static `List<ProviderConfigProperty> configProperties`, `getId()`, `getDisplayType()`, `getDisplayCategory()` returning the inherited `TOKEN_MAPPER_CATEGORY` constant, `getHelpText()`, `getConfigProperties()`.

**How the switches work (important, saves you effort).** `AbstractOIDCProtocolMapper.transformIDToken/transformAccessToken/transformUserInfoToken/transformIntrospectionToken` already gate on `OIDCAttributeMapperHelper.includeInIDToken(...)` etc. and then call the protected `setClaim(...)` hook. So you only override `setClaim`, and you only need the four include-in-* config properties registered so the admin console can toggle them — check `OIDCAttributeMapperHelper` for the helper that adds them in one call (I believe `addIncludeInTokensConfig(configProperties, YourMapper.class)`; verify the exact name/signature before use). Since the claim name is fixed, you can write it directly into `token.getOtherClaims().put("email_domain", domain)` rather than using `mapClaim` with a configurable claim name. Guard: email null/blank or no `@` → return without touching the token.

**Registration (easy to forget).** Add the fully-qualified class name to `services/src/main/resources/META-INF/services/org.keycloak.protocol.ProtocolMapper`. Without this the provider id will not resolve at runtime.

**"Shipped out of the box".** `services/src/main/java/org/keycloak/protocol/oidc/OIDCLoginProtocolFactory.java`: field `builtins` (~line 190), populated in `initBuiltIns()` (~lines 192–291, called from `init()`), exposed by `getBuiltinMappers()` and surfaced to the admin console via server-info/builtin-protocol-mappers. Build a `ProtocolMapperModel` (name, protocol `OIDCLoginProtocol.LOGIN_PROTOCOL`, protocolMapper = your PROVIDER_ID, config with the include flags "true") and `builtins.put(NAME, model)`. Do NOT also attach it to the default client scopes (`profile`/`email`, created further down that file, ~lines 302–395) — that would inject the claim into every token in every new realm and will break existing token-content assertions.
