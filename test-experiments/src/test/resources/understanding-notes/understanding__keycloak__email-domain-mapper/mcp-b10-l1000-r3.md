Clone `org/keycloak/protocol/oidc/mappers/FullNameMapper.java` — it is the exact pattern: extend `AbstractOIDCProtocolMapper`, implement `OIDCAccessTokenMapper, OIDCIDTokenMapper, UserInfoTokenMapper, TokenIntrospectionTokenMapper` (these interfaces are what the include-in-X admin switches key off), static block calling `OIDCAttributeMapperHelper.addIncludeInTokensConfig(configProperties, X.class)`, `getDisplayCategory()` = `TOKEN_MAPPER_CATEGORY`, override `setClaim(IDToken, ProtocolMapperModel, UserSessionModel)` and put `email_domain` in `token.getOtherClaims()` only for a non-empty part after '@'.

Read the email off the token. `IDToken.getEmail()` may be null: the builtin "email" mapper writes into `getOtherClaims()` ("email" is absent from OIDCAttributeMapperHelper's tokenPropertySetters) — check both (I'm unsure which wins).
