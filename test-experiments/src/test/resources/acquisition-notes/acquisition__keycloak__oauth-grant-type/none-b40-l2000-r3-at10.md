## Hand-off note

**Repo**: Keycloak, multi-module Maven (Java 17). Everything relevant sits in two modules.

**What to imitate**
Grant types at the token endpoint are pluggable providers.
- SPI contracts: `server-spi-private/.../org/keycloak/protocol/oidc/grants/` — `OAuth2GrantType` (extends `Provider`: `getEventType()`, `getTokenParameterNames()`, `process(Context)`, optional `preProcess(...)`, `isTokenAllowed(...)`), `OAuth2GrantTypeFactory` (adds `getShortcut()`, whose javadoc already states the shortcut must be unique across grants), and `OAuth2GrantTypeSpi` (SPI name `oauth2-grant-type`, internal).
- Implementations: `services/.../protocol/oidc/grants/` — a `XxxGrantType` + `XxxGrantTypeFactory` pair per grant, sharing `OAuth2GrantTypeBase`. `RefreshTokenGrantType`/`RefreshTokenGrantTypeFactory` is the model to copy for the new renewal grant; also present: AuthorizationCode, ClientCredentials, ResourceOwnerPasswordCredentials, TokenExchange, PreAuthorizedCode, Permission, JWTAuthorizationGrant, `ciba/CibaGrantType`.

**Changes and their dependencies**
1. Add the new grant-type identifier constant next to the others in `core/.../org/keycloak/OAuth2Constants.java` (holds `REFRESH_TOKEN`, `DEVICE_CODE_GRANT_TYPE`, `CIBA_GRANT_TYPE`, …).
2. Add the grant type + factory in the services grants package, with a shortcut distinct from every existing factory's.
3. Reject ordinary interactive refresh tokens before minting: `core/.../util/TokenUtil` distinguishes them (`TOKEN_TYPE_REFRESH` vs `TOKEN_TYPE_OFFLINE`, `isOfflineToken(String)`, `getRefreshToken(...)`). Fail with an `invalid_grant` protocol error — see `core/.../OAuthErrorException.java` — not an exception that becomes a 500.
4. Advertise it: `services/.../protocol/oidc/OIDCWellKnownProvider.java`, backed by `core/.../protocol/oidc/representations/OIDCConfigurationRepresentation.java`; `OIDCLoginProtocol` also references grant types.
5. Shortcut-uniqueness must abort startup. The javadoc states the rule, but no enforcement code was located — verify whether it exists and add it if not.

**Easy to miss**
- How factories get registered/enabled (provider registration files, `GrantTypeEndpointRestrictionValidator` in `services/.../managers`) was not confirmed — check before assuming the grant is reachable.
- Auditing hinges on the `EventType` you return, plus `grant_type` in `server-spi-private/.../events/Details`.

**Verification**
Integration tests live in `tests/base/src/test/java/org/keycloak/tests/oauth/` (`OfflineTokenBasicFlowTest` is the nearest analogue) using `test-framework/oauth` and `EventAssertion`. Cover: long-lived credential succeeds; interactive credential yields `invalid_grant`; new grant appears in the discovery document.
