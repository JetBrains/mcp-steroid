# Hand-off: dedicated refresh grant for offline tokens

## Where the work lives

Grant types are a Keycloak SPI: `oauth2-grant-type` (`server-spi-private/.../protocol/oidc/grants/OAuth2GrantTypeSpi.java`), provider interface `OAuth2GrantType`, factory interface `OAuth2GrantTypeFactory` (both same package). Implementations live in `services/.../protocol/oidc/grants/`, all extending `OAuth2GrantTypeBase`.

**Model to imitate:** `RefreshTokenGrantType` + `RefreshTokenGrantTypeFactory` (id = `OAuth2Constants.REFRESH_TOKEN`, `GRANT_SHORTCUT = "rt"`). Its `process()` reads the `refresh_token` form param, fires `TokenRefreshContext` client policy, calls `tokenManager.verifyRefreshToken(...)`, builds a `RefreshTokenContext` (record in `.../protocol/oidc/refresh/`, note it is typed on `RefreshTokenGrantType`), picks a `RefreshTokenProvider` by `order()`/`supports()`, then MTLS binding, `TokenRefreshResponseContext`, response build. Errors are raised as `CorsErrorResponseException` (and `OAuthErrorException` inside the try) — use `OAuthErrorException.INVALID_GRANT`, as `TokenManager.verifyRefreshToken` does, so failures stay protocol errors, not 500s.

Offline vs regular tokens are distinguished by the refresh token's type: `TokenUtil.TOKEN_TYPE_OFFLINE` vs `TOKEN_TYPE_REFRESH` (see `TokenManager` ~line 353 and `AbstractRefreshTokenProvider` ~line 157). Reject the non-offline case before minting.

## Dependent changes

1. New grant type + factory in `services/.../grants/`; new grant-type constant probably in `core/.../OAuth2Constants.java` (existing pattern: `DEVICE_CODE_GRANT_TYPE`, `CIBA_GRANT_TYPE`).
2. Register the factory in `services/src/main/resources/META-INF/services/org.keycloak.protocol.oidc.grants.OAuth2GrantTypeFactory` — without this the endpoint won't resolve it (`TokenEndpoint.checkGrantType()` does `session.getProvider(OAuth2GrantType.class, grantType)`).
3. Pick a shortcut unique against: rt, ci, dg, te, ro, pc, pg, cc, ag, and `AuthorizationCodeGrantTypeFactory.GRANT_SHORTCUT` (unread). Duplicates fail startup in `DefaultTokenContextEncoderProviderFactory.postInit` (map-size check → `IllegalStateException`).
4. Metadata is automatic: `OIDCWellKnownProvider.getGrantTypesSupported()` streams all registered factories, so no list to edit.

## Verify

Integration tests use the `org.keycloak.testframework` style (`tests/base/.../oauth/OfflineTokenRefreshTest.java`, `RefreshTokenTest.java`). `RefreshRequest` (`tests/utils-shared/.../util/oauth/`) hardcodes `grant_type=refresh_token` in `initRequest()` — a new request helper or parameter override is needed to exercise the new grant. No test asserting an exact `grant_types_supported` list was found.
