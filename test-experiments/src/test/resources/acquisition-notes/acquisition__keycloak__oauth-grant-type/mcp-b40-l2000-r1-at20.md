# Hand-off: dedicated offline-token refresh grant

## What to imitate
Grant types are SPI providers: interface `org.keycloak.protocol.oidc.grants.OAuth2GrantType` and `OAuth2GrantTypeFactory` (+`OAuth2GrantTypeSpi`) in `server-spi-private/.../protocol/oidc/grants/`; implementations live in `services/src/main/java/org/keycloak/protocol/oidc/grants/` (AuthorizationCode, RefreshToken, ClientCredentials, TokenExchange, device, ciba, …). Most extend `OAuth2GrantTypeBase`.

The closest model is `RefreshTokenGrantType` + `RefreshTokenGrantTypeFactory`. Copy that pair. `OAuth2GrantType` requires `getEventType()`, `getTokenParameterNames()`, `process(Context)`; optional `preProcess`, `getSupportedMultivaluedRequestParameters`, `isTokenAllowed`. The factory supplies `getId()` (the wire `grant_type` value, usually an `OAuth2Constants` field) and `getShortcut()` (factories define it as a `GRANT_SHORTCUT` constant; known values include `ci` for CIBA and `dg` for device — check every factory in that package for a free two-letter code).

## Changes and their dependencies
1. New grant class + factory in `services/.../protocol/oidc/grants/`.
2. Register the factory in `services/src/main/resources/META-INF/services/org.keycloak.protocol.oidc.grants.OAuth2GrantTypeFactory` — without this the grant is invisible to the token endpoint and to metadata.
3. Likely a new constant in `core/src/main/java/org/keycloak/OAuth2Constants.java` (has `REFRESH_TOKEN`, `OFFLINE_ACCESS`, `CIBA_GRANT_TYPE`, etc.; no offline-grant name exists yet — the name is not fixed anywhere in the repo).
4. Offline vs online is decided by the token's type: `TokenUtil.TOKEN_TYPE_OFFLINE` vs `TOKEN_TYPE_REFRESH` (see `TokenManager.verifyRefreshToken`, `DefaultRefreshTokenProvider.supports`). Reject a non-offline token by throwing/returning `OAuthErrorException.INVALID_GRANT`, as `TokenManager` does, before delegating to the refresh logic.

Nothing else registers grant types: `TokenEndpoint.checkGrantType()` resolves `session.getProvider(OAuth2GrantType.class, grantType)`, and `OIDCWellKnownProvider.getGrantTypesSupported()` streams all `OAuth2GrantType` factory ids (plus `implicit`), so metadata updates itself.

## Easy to miss
- Shortcut uniqueness is enforced at boot in `DefaultTokenContextEncoderProviderFactory.postInit` (map-size comparison → `IllegalStateException`). A duplicate id or shortcut fails startup.
- `AbstractWellKnownProviderTest` asserts `getGrantTypesSupported().size() == 10` and an explicit list — both must be updated.
