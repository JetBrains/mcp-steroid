**Hand-off note: dedicated token-endpoint grant for long-lived (offline) credential renewal**

**What to imitate.** Grant types are pluggable via the `oauth2-grant-type` SPI (`OAuth2GrantTypeSpi`, name `"oauth2-grant-type"`, internal) with the interfaces in `server-spi-private/.../org/keycloak/protocol/oidc/grants/`: `OAuth2GrantType` (`getEventType`, `getTokenParameterNames`, `preProcess`, `Response process(Context)`, `isTokenAllowed`) and `OAuth2GrantTypeFactory` (adds `getShortcut()`). Implementations live in `services/.../protocol/oidc/grants/`. The closest model is the pair `RefreshTokenGrantType` / `RefreshTokenGrantTypeFactory` (id `OAuth2Constants.REFRESH_TOKEN`, `GRANT_SHORTCUT = "rt"`): it reads the `refresh_token` form param, rejects a missing one with `CorsErrorResponseException(cors, INVALID_REQUEST, …, 400)`, fires `TokenRefreshContext`, verifies through `tokenManager.verifyRefreshToken`, then delegates to the highest-`order()` `RefreshTokenProvider` that `supports(RefreshTokenContext)`, does mTLS-HoK binding and `TokenRefreshResponseContext`. Most shared minting logic is in `OAuth2GrantTypeBase` (`setContext`, `createTokenResponseBuilder`, which stamps `Constants.GRANT_TYPE` on the client session context). For the rejection path imitate `AuthorizationCodeGrantType`: `event.error(...)` plus `CorsErrorResponseException(cors, OAuthErrorException.INVALID_GRANT, "…", 400)` — thrown before any response builder is created.

**Changes and their dependencies.**
1. New grant type + factory class in `services/.../protocol/oidc/grants/`, with a grant-name constant likely belonging in `core/.../org/keycloak/OAuth2Constants.java`.
2. Register the factory in `services/src/main/resources/META-INF/services/org.keycloak.protocol.oidc.grants.OAuth2GrantTypeFactory` (currently 10 entries) — without this the grant is invisible.
3. Advertise it in `services/.../protocol/oidc/OIDCWellKnownProvider.java`; the field is `grant_types_supported` in `core/.../protocol/oidc/representations/OIDCConfigurationRepresentation.java`.

**Easy to miss.** `getShortcut()` must be new: `DefaultTokenContextEncoderProviderFactory.postInit` builds shortcut↔grant maps over all factories and throws `IllegalStateException` on a size mismatch, so a clashing shortcut fails server startup. Known taken values: `"ac"`, `"rt"`; the other eight factories' shortcuts were not inspected — check them all. How an offline/long-lived credential is distinguished from an ordinary one is not established here; `TokenUtil.TOKEN_TYPE_OFFLINE` is used in `OAuth2GrantTypeBase` and the verified `RefreshToken` is available, so start there.
