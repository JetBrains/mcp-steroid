**Hand-off note — new offline-only refresh grant at the token endpoint**

**What to imitate**
- Grants are an SPI: `OAuth2GrantType` (+ `OAuth2GrantTypeFactory`, `OAuth2GrantTypeSpi`) in `server-spi-private/.../protocol/oidc/grants/`. The factory interface adds only `getShortcut()` on top of the usual provider factory.
- Implementations live in `services/src/main/java/org/keycloak/protocol/oidc/grants/`. Closest model: `RefreshTokenGrantType` (extends `OAuth2GrantTypeBase`, overrides `process`, `getEventType`, `getTokenParameterNames`) plus `RefreshTokenGrantTypeFactory`. It reads `OAuth2Constants.REFRESH_TOKEN` from `formParams`, fires client policies, calls `tokenManager.verifyRefreshToken(...)`, builds a `RefreshTokenContext`, then picks a `RefreshTokenProvider` (impls: `DefaultRefreshTokenProvider`, `AbstractRefreshTokenProvider`, `OID4VCIRefreshTokenProvider`) and calls `refreshAccessToken`. Errors are surfaced as `CorsErrorResponseException` with `OAuthErrorException` codes, so use `INVALID_GRANT` there rather than letting an exception escape.
- Best end-to-end template for "add a grant": commit `a25a0268de` (JWT Authorization Grant). It touched `common/.../Profile.java`, `core/.../OAuth2Constants.java`, the grant type + factory, the services registration file, an integration test under `tests/.../oauth/`, and test-client helpers (`AbstractOAuthClient`, a `*Request` class).

**Change dependencies**
1. Add the grant-type identifier constant in `core/src/main/java/org/keycloak/OAuth2Constants.java`.
2. New grant type + factory; the factory's `getId()` must be the new grant name and `getShortcut()` must be unique.
3. Register the factory in `services/src/main/resources/META-INF/services/org.keycloak.protocol.oidc.grants.OAuth2GrantTypeFactory`.
4. Offline check before minting: `TokenUtil.isOfflineToken(...)` / `isOfflineTokenRequested(...)` and `TokenUtil.TOKEN_TYPE_OFFLINE` (`core/.../util/TokenUtil.java`).

**Easy to miss**
- Discovery metadata needs no edit: `OIDCWellKnownProvider.getGrantTypesSupported()` (~line 298) enumerates registered `OAuth2GrantType` factories; registration alone publishes it.
- Shortcut uniqueness is enforced at startup in `DefaultTokenContextEncoderProviderFactory.postInit` (map-size comparison → `IllegalStateException`).
- Exact current `getId`/`getShortcut` values of existing factories were not inspected; check them before choosing yours.

**Verify**: server boots (no duplicate-shortcut failure); `grant_types_supported` lists the new name; offline token succeeds, ordinary refresh token gets `invalid_grant`. Model the test on `JWTAuthorizationGrantTest`.
