# Hand-off note: dedicated non-interactive token-renewal grant

## Where you are

This is Keycloak. Grant types at the token endpoint are pluggable providers behind the `oauth2-grant-type` SPI (`server-spi-private/.../protocol/oidc/grants/OAuth2GrantTypeSpi.java`, `OAuth2GrantType`, `OAuth2GrantTypeFactory`). Concrete grants live in `services/src/main/java/org/keycloak/protocol/oidc/grants/`.

## What to imitate

The model to copy is the pair `RefreshTokenGrantType` / `RefreshTokenGrantTypeFactory`:

- The factory implements `OAuth2GrantTypeFactory`: `getId()` returns the wire `grant_type` value (currently `OAuth2Constants.REFRESH_TOKEN`), `getShortcut()` returns a short unique string (`GRANT_SHORTCUT = "rt"`), plus trivial `create/init/postInit/close`.
- `RefreshTokenGrantType extends OAuth2GrantTypeBase` and implements `process(Context)`: reads the `refresh_token` form param, triggers client policies, calls `tokenManager.verifyRefreshToken(...)`, builds a `RefreshTokenContext`, selects a `RefreshTokenProvider` by order/`supports`, builds the response, and translates `OAuthErrorException`/`ClientPolicyException` into `CorsErrorResponseException` with an OAuth error code and status. Follow that pattern for the "wrong credential kind" rejection: throw a `CorsErrorResponseException` with the invalid-grant error and a 4xx status, before any token building.

`TokenEndpoint.processGrantRequest` reads `grant_type` from the form, then resolves the grant with `session.getProvider(OAuth2GrantType.class, grantType)` (around lines 131/223-233) — so a new grant needs no endpoint change beyond registration.

## Changes and their dependencies

1. New grant type + factory class in the grants package, with a distinct `getId()` and a new, unique `getShortcut()`.
2. Register the factory in `services/src/main/resources/META-INF/services/org.keycloak.protocol.oidc.grants.OAuth2GrantTypeFactory` (currently 10 entries) — otherwise the grant is invisible.
3. Advertise it in `grant_types_supported`, produced by `services/.../protocol/oidc/OIDCWellKnownProvider.java` (representation field: `OIDCConfigurationRepresentation.grantTypesSupported`, `core` module). The provider already streams grant provider factories, so check whether the list is derived or hard-coded before editing.
4. Shortcut uniqueness enforcement at startup: shortcuts are consumed by the token-context encoder (`protocol/oidc/encode/AccessTokenContext`, `DefaultTokenContextEncoderProvider(Factory)`), which is the likely place for a duplicate-shortcut startup failure. Unverified — inspect these first.

## Easy to miss

`services/target/classes/META-INF/services/...` is stale build output; edit only `src/main/resources`.
