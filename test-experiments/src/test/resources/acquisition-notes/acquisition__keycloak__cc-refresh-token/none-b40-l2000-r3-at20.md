**Hand-off note: enforce "no refresh token from client credentials grant" under the `strict` security profile**

**Mechanism to use.** Security profiles are thin JSON descriptors in `services/src/main/resources`: `strict-security-profile.json`, `lax-…`, `none-…`. Each only names a global client-profiles file and a client-policies file — `strict` points at `keycloak-default-client-profiles.json` and `keycloak-strict-client-policies.json` (both in the same resources dir; contents not yet inspected). `DefaultSecurityProfileProviderFactory` (`services/.../services/securityprofile`) reads `<name>.json` (default `none-security-profile`) from classpath or `conf/`, then validates it via `ClientPoliciesUtil.readGlobalClientProfilesRepresentation/readGlobalClientPoliciesRepresentation`. So the enforcement should be a **client policy executor** wired into the default client profile and referenced by the strict policies file — nothing needs to change in the SPI (`server-spi-private/.../securityprofile`) or `SecurityProfileConfiguration` (core).

**What to imitate.** `services/src/main/java/org/keycloak/services/clientpolicy/executor/` holds ~40 `XExecutor` + `XExecutorFactory` pairs; the closest analogues in intent are `RejectResourceOwnerPasswordCredentialsGrantExecutor`, `ConfidentialClientAcceptExecutor` and `SuppressRefreshTokenRotationExecutor*`. Contracts live in `server-spi-private/.../clientpolicy/executor/` and `server-spi/.../clientpolicy/` (`ClientPolicyEvent`, `ClientPolicyContext`, `ClientPolicyException`); dispatch is `DefaultClientPolicyManager`.

**The setting.** `OIDCConfigAttributes.USE_REFRESH_TOKEN_FOR_CLIENT_CREDENTIALS_GRANT` = `"client_credentials.use_refresh_token"` (server-spi-private), read/written by `OIDCAdvancedConfigWrapper.is/setUseRefreshTokenForClientCredentialsGrant` (defaults to `"false"`), consumed by `protocol/oidc/grants/ClientCredentialsGrantType`.

**Easy to miss.** Cover both admin-REST and dynamic-registration create/update events, plus updates that omit the attribute (fall back to the stored client value — the wrapper's `false` default makes an absent attribute look disabled). Restrict to confidential OIDC clients. `none` has null policies, so a profile-less server must be unaffected. Files under `services/target/classes/` are build output — edit `src/main/resources`.

**Verification.** `tests/base/src/test/java/org/keycloak/tests/securityprofile/LaxSecurityProfileTest.java` is the pattern for a strict-profile test (no strict counterpart exists yet); `test-framework` `ClientPolicyBuilder`/`ClientProfileBuilder` help build fixtures. Registration of new executor factories (META-INF/services) was not inspected — verify against an existing executor.
