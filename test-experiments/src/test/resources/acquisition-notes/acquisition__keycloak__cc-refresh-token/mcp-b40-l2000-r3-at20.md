**Goal:** a new client-policy executor that forbids `client_credentials.use_refresh_token` on confidential OIDC clients, wired into the `strict` security profile.

**Wiring (all under `services/`):**
- `src/main/resources/keycloak-default-client-profiles.json` — add the executor (with `"auto-configure": "true"`) to the `oauth-2-1-for-confidential-client` profile. That profile is referenced by the `Openid-connect OAuth 2.1 confidential client` policy in `keycloak-strict-client-policies.json` (and in `keycloak-lax-client-policies.json` — decide deliberately whether lax gets it too); `strict-security-profile.json` points at both files. The policy already carries the `client-type: openid-connect` + `client-access-type: confidential` conditions, so no extra condition work is needed and servers without a security profile stay unaffected.
- `src/main/java/org/keycloak/services/clientpolicy/executor/` — new `…Executor` + `…ExecutorFactory` (imitate `RejectImplicitGrantExecutor`/`RejectResourceOwnerPasswordCredentialsGrantExecutorFactory`, which sit in the same profile) with a `Configuration` holding the `@JsonProperty("auto-configure")` flag.
- `src/main/resources/META-INF/services/org.keycloak.services.clientpolicy.executor.ClientPolicyExecutorProviderFactory` — append the new factory; forgetting this silently disables it.

**Executor logic:** handle `REGISTER` and `UPDATE` from `ClientCRUDContext`; auto-configure then validate the proposed `ClientRepresentation`. Use `OIDCAdvancedConfigWrapper.fromClientRepresentation(rep).isUseRefreshTokenForClientCredentialsGrant()/set…` (attribute constant `OIDCConfigAttributes.USE_REFRESH_TOKEN_FOR_CLIENT_CREDENTIALS_GRANT`, defaults to `"false"` when absent). For the "update omits the attribute but the stored client has it on" case copy `ConsentRequiredExecutor.beforeUpdate`, which consults `ClientCRUDContext.getTargetClient()`; note the wrapper reads only the model when built from a `ClientModel`, so build one wrapper per source. Throw `ClientPolicyException` with `OAuthErrorException.INVALID_CLIENT_METADATA` (as `RejectImplicitGrantExecutor`/`HolderOfKeyEnforcerExecutor` do) — Errors.INVALID_REGISTRATION is the older style.

**Verify:** new-framework tests in `tests/base/.../tests/securityprofile/` — imitate `LaxSecurityProfileTest`, whose server config sets `spiOption("security-profile","default","name","strict-security-profile")`, and use `AbstractClientPoliciesTest` helpers (`createClientByAdmin`, `updateClientByAdmin`, `createClientDynamically`, `updateClientDynamically`) for admin-API and DCR coverage. Also relevant: legacy `OAuth2_1ConfidentialClientTest`, and `DefaultSecurityProfileProverFactoryTest` (parses all three profile JSONs — catches malformed edits). Runtime honouring of the switch lives in `ClientCredentialsGrantType`. Whether docs (`docs/guides/securing-apps/partials/oidc/oauth21-support.adoc`, which does not enumerate restrictions) or admin-UI resources need updating is unknown.
