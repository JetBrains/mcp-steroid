## Hand-off note: reject refresh tokens from client credentials grant under `strict`

### What to imitate
Client policy executors live in `services/src/main/java/org/keycloak/services/clientpolicy/executor/`, each as a pair `XxxExecutor.java` + `XxxExecutorFactory.java`. The closest models are `RejectImplicitGrantExecutor(Factory)` and `RejectResourceOwnerPasswordCredentialsGrantExecutor(Factory)` — both are "reject a grant type" executors; `RejectRequestExecutor` is another example. Their interface contract is `org.keycloak.services.clientpolicy.executor.ClientPolicyExecutorProviderFactory` in `server-spi-private`. Every factory must be registered in `services/src/main/resources/META-INF/services/org.keycloak.services.clientpolicy.executor.ClientPolicyExecutorProviderFactory`; forgetting this line is the classic silent failure.

### Wiring the strict profile
Security profiles are JSON resources in `services/src/main/resources/`: `strict-security-profile.json`, `lax-…`, `none-…`. `strict-security-profile.json` is tiny and only names two resources: `keycloak-default-client-profiles` and `keycloak-strict-client-policies`, i.e. `keycloak-default-client-profiles.json` and `keycloak-strict-client-policies.json` in the same directory. Client profiles are lists of named profiles each holding an `executors` array of `{"executor": "<factory id>", "configuration": {…}}`; e.g. `fapi-2-security-profile` uses `{"executor":"reject-implicit-grant","configuration":{"auto-configure":"true"}}`. So the new executor must be added to a profile in `keycloak-default-client-profiles.json` and that profile must be referenced by a policy in `keycloak-strict-client-policies.json` (contents not inspected — read it first to see which policies strict enables and how conditions like confidential/OIDC-only are expressed; the existing `confidential-client` executor may be relevant).

Order: SPI executor → service registration → profile JSON → strict policy JSON. Nothing outside these should change, so a server with no profile keeps today's behaviour.
