**Hand-off note: forbid refresh tokens for the client-credentials grant under the `strict` security profile**

**The mechanism to work with.** Security profiles are JSON files in `services/src/main/resources`: `strict-security-profile.json`, `lax-…`, `none-…`. Each names a client-profiles file and a client-policies file (`strict` → `keycloak-default-client-profiles.json` + `keycloak-strict-client-policies.json`; `none` has `"client-policies": null`, so a server without a profile gets no policies and is automatically unaffected). `DefaultSecurityProfileProviderFactory` (`services/.../services/securityprofile/`) loads `<name>.json` (default `none-security-profile`) from classpath or `conf/`, and validates its contents through `ClientPoliciesUtil.readGlobalClientProfiles/PoliciesRepresentation`. Copies under `services/target/classes` are build output; edit only `src/main/resources`.

**What to add.** The enforcement belongs in a client-policy executor: see `services/src/main/java/org/keycloak/services/clientpolicy/executor/` (`FullScopeDisabledExecutor`, `ConsentRequiredExecutor`, `SecureRequestObjectExecutor`) and, for factory shape, `protocol/oid4vc/clientpolicy/CredentialClientPolicyExecutorFactory`. Profiles reference executors by string id plus a `configuration` block (`auto-configure` is a common option, e.g. in `keycloak-default-client-profiles.json`), so the executor needs a factory whose id matches the JSON; check how other executor factories are registered as providers — the record does not cover that.

The attribute is `OIDCConfigAttributes.USE_REFRESH_TOKEN_FOR_CLIENT_CREDENTIALS_GRANT` (`client_credentials.use_refresh_token`, in `server-spi-private`), read/written via `OIDCAdvancedConfigWrapper`, which can wrap either a `ClientModel` or a `ClientRepresentation` — you need the model form for updates that omit the attribute, and the representation form for the incoming request. The getter already defaults to `"false"`. Runtime consumer: `ClientCredentialsGrantType.useRefreshToken()`.

**Then wire it up:** add the executor to a profile in `keycloak-default-client-profiles.json` and make `keycloak-strict-client-policies.json` (not the lax one) apply that profile. Confirm which `ClientPolicyEvent` values cover admin-REST and dynamic-registration create/update; both must be handled, and failures must surface as `ClientPolicyException`. Restrict to confidential OIDC clients.

**Verification.** Follow `tests/base/src/test/java/org/keycloak/tests/securityprofile/LaxSecurityProfileTest.java` for a profile-scoped integration test; `services/src/test/java/.../DefaultSecurityProfileProverFactoryTest` and `testsuite/.../client/policies/AbstractClientPoliciesTest` are the other relevant harnesses. Existing tests that set the attribute to `true` (`tests/base/.../oauth/RefreshTokenTest`, `OfflineToken*Test`, `testsuite/.../ServiceAccountTest`, `AuthzClientCredentialsTest`) must keep passing without a profile.
