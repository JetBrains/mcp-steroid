**Hand-off note — enforce "no refresh token from client credentials" under the `strict` security profile**

**Where the pieces live**
- Built-in profiles: `services/src/main/resources/{none,strict,lax}-security-profile.json`. Each names a client-profiles set and a client-policies set; `strict` uses `keycloak-default-client-profiles` + `keycloak-strict-client-policies`, both in `services/src/main/resources/`.
- `keycloak-strict-client-policies.json` already has the policy you need: *"Openid-connect OAuth 2.1 confidential client"* (conditions `client-type: openid-connect` + `client-access-type: confidential`) applying the profile `oauth-2-1-for-confidential-client`, which is defined in `keycloak-default-client-profiles.json`. Adding a new executor entry to that profile gives you the "out of the box under strict, confidential OIDC only" requirement for free — no new policy or condition needed.
- Executors: `services/src/main/java/org/keycloak/services/clientpolicy/executor/`, one `XExecutor` + `XExecutorFactory` pair each, factory holding `PROVIDER_ID` and config properties.

**Model to imitate**
`RejectResourceOwnerPasswordCredentialsGrantExecutor(Factory)` (`reject-ropc-grant`). It implements `ClientPolicyExecutorProvider<Configuration>`, with a `Configuration` extending `ClientPolicyExecutorConfigurationRepresentation` (`@JsonProperty("auto-configure")`), and in `executeOnEvent` handles `REGISTER`/`UPDATE` by casting to `ClientCRUDContext`, calling auto-configure then validate on `getProposedClientRepresentation()`, throwing `ClientPolicyException(OAuthErrorException.INVALID_CLIENT_METADATA, ...)`. Both admin REST and dynamic client registration go through these same REGISTER/UPDATE events, so one executor covers both paths.

**Easy to miss**
- The ROPC model dereferences the representation flag unconditionally (`rep.isDirectAccessGrantsEnabled().booleanValue()`); your flag is an OIDC advanced setting (see `OIDCAdvancedConfigWrapper`) and may be absent on the representation. An UPDATE that omits it must still fail if the stored client has it on, so validation must fall back to the existing client, not only the proposed representation; a REGISTER that omits it must end up off (auto-configure).
- Factory registration mechanism was not confirmed — check how sibling executor factories are declared as providers.
