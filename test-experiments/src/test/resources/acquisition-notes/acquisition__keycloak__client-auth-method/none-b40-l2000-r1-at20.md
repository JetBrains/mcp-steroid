# Hand-off note: self-signed TLS client authentication (`self_signed_tls_client_auth`)

## What to imitate

The new authenticator belongs next to the existing ones in
`services/src/main/java/org/keycloak/authentication/authenticators/client/`.
`X509ClientAuthenticator` (PROVIDER_ID `client-x509`) is the closest model: it extends
`AbstractClientAuthenticator` (which implements both `ClientAuthenticator` and
`ClientAuthenticatorFactory` and supplies the trivial lifecycle methods, so only the
authenticator-specific methods need writing). Reuse its opening half verbatim in spirit:
obtain `X509ClientCertificateLookup` from the session and call
`getCertificateChain(context.getHttpRequest())`; resolve `client_id` from form data, then
query params, then the session attribute; `context.setClient`, `context.getEvent().client(...)`;
fail with `CLIENT_NOT_FOUND` / `CLIENT_DISABLED`; build error bodies with
`ClientAuthUtil.errorResponse`. Then diverge: instead of subject-DN/CA-DN matching, compare
the presented leaf certificate against the certificate stored on the client. For reading that
stored certificate, `CertificateInfoHelper` is the place to look
(`getCertificateFromClient(client, attributePrefix)` returns a `CertificateRepresentation`
whose `certificate` is a PEM); `PemUtils` (`common/src/main/java/org/keycloak/common/util/PemUtils.java`)
is the PEM/certificate helper. Comparison must be exact bytes — the same DN plus the same key
must still fail — so do not compare DNs or public keys, and do not touch any truststore.
Which credential attribute prefix the admin console writes was not established; confirm before
coding.

## Dependent changes

1. Register the class in
   `services/src/main/resources/META-INF/services/org.keycloak.authentication.ClientAuthenticatorFactory`
   (currently lists five authenticators including `X509ClientAuthenticator`).
2. Discovery: `services/.../protocol/oidc/OIDCWellKnownProvider.java` builds
   `token_endpoint_auth_methods_supported`; the OIDC name for the existing X509 method is
   `OIDCLoginProtocol.TLS_CLIENT_AUTH = "tls_client_auth"`, so add a sibling constant there.
3. Dynamic registration: `services/.../clientregistration/oidc/DescriptionConverter.java`
   maps the auth-method name to the provider id.
4. Client profiles: `services/src/main/resources/keycloak-default-client-profiles.json`
   lists `client-x509` in seven places — the new provider id likely needs adding alongside.

Easy to miss: `DefaultClientValidationProvider` (~line 609) and
`TlsClientAuthCASubjectDNExecutor` gate on `client-x509` and require CA subject DN; make sure
the new id is not caught by those rules.
