**Hand-off note: self-signed-certificate client authentication**

**What to imitate**
`services/src/main/java/org/keycloak/authentication/authenticators/client/X509ClientAuthenticator.java` (`PROVIDER_ID = "client-x509"`) is the model. Copy its front half almost verbatim: obtain the `X509ClientCertificateLookup` provider from the session and call `getCertificateChain(context.getHttpRequest())`; resolve `client_id` from decoded form params, then query params, then the session attribute `"client_id"`; on failure use `ClientAuthUtil.errorResponse(...)` + `context.challenge(...)`, or `context.failure(CLIENT_NOT_FOUND / CLIENT_DISABLED)`; `GeneralSecurityException` → `context.attempted()`. Drop everything downstream that concerns subject-DN matching (`ATTR_SUBJECT_DN`, `ATTR_CA_SUBJECT_DN`, `ATTR_ALLOW_REGEX_PATTERN_COMPARISON`, the custom-OID `X500Principal` machinery, `CertificateValidator`) and instead compare the presented certificate against the one stored on the client. The tail of `X509ClientAuthenticator` was not read; it imports `OIDCLoginProtocol` and `ProviderConfigProperty`, so check there for the method that advertises the protocol auth method in discovery and for config-property declarations.

New class extends `AbstractClientAuthenticator` (same package), which supplies all `ClientAuthenticatorFactory` no-ops. Likely helpers for reading the stored certificate: `services/.../services/util/CertificateInfoHelper.java` and `common/.../common/util/PemUtils.java` — neither was inspected. `JWTClientAuthenticator` / `FederatedJWTClientAuthenticator` in the same package are further examples.

**Registration**
Add the class to `services/src/main/resources/META-INF/services/org.keycloak.authentication.ClientAuthenticatorFactory` (six entries today). Ignore the `target/classes` copies; the arquillian `testsuite-providers` module has its own separate file.

**Easy to miss**
Places keyed on `client-x509` that may need the new id: `DefaultClientValidationProvider` (~line 609, validates the x509 attributes — the new type must not require them), `TlsClientAuthCASubjectDNExecutor`, `OIDCAdvancedConfigWrapper` (lines ~301-323).

**Verification**
`ClientPoliciesV2Test` (rest/admin-v2/tests, lines ~476, ~513 enumerate accepted authenticators) and `FAPICIBATest` (integration-arquillian base) show how profiles tolerate x509 clients; extend those lists/tests. Confirm the method name appears in the realm's discovery document.
