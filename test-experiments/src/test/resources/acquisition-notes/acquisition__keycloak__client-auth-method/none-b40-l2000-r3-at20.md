**Hand-off note: self-signed-certificate client authentication (mTLS)**

**Model to imitate.** `services/.../authentication/authenticators/client/X509ClientAuthenticator.java` (`PROVIDER_ID = "client-x509"`, extends `AbstractClientAuthenticator`). Reuse its shape: resolve `client_id` from form data → query params → session attribute, fail with `CLIENT_NOT_FOUND`/`CLIENT_DISABLED`, obtain the chain via `session.getProvider(X509ClientCertificateLookup.class).getCertificateChain(httpRequest)`, `context.attempted()` when no cert. Drop its subject-DN/CA-DN/regex logic (`ATTR_SUBJECT_DN`, `ATTR_CA_SUBJECT_DN`, `ATTR_ALLOW_REGEX_PATTERN_COMPARISON`) and the `CertificateValidator` trust-chain path; instead compare the leaf certificate against the client's stored one. The stored certificate is a client attribute read through `services/.../services/util/CertificateInfoHelper.getCertificateFromClient(client, prefix)`; the existing prefix in use is `JWTClientAuthenticator.ATTR_PREFIX = "jwt.credential"` (`jwt.credential.certificate`). Comparing full encoded bytes (not subject/key) is what makes a re-issued cert with identical DN and key fail.

For the precedent of adding a whole new client authenticator, see the commit "Experimental federated client authentication" (`FederatedJWTClientAuthenticator`): new class + registration + flow entry + tests; it was feature-gated via `Profile` — decide whether gating is wanted here.
