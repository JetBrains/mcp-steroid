**Hand-off: self-signed-certificate client authentication**

**Imitate**
`services/src/main/java/org/keycloak/authentication/authenticators/client/X509ClientAuthenticator.java` (`PROVIDER_ID = "client-x509"`, extends `AbstractClientAuthenticator`, same package). Its first half is exactly what you need: get `X509ClientCertificateLookup` from the session, `provider.getCertificateChain(request)`, resolve `client_id` from form data → query params → session attribute `"client_id"`, `context.setClient`, enabled check, `ClientAuthUtil.errorResponse` for challenges. Replace its subject-DN/CA-DN/`CertificateValidator` logic with a byte comparison of the leaf certificate against the client's stored certificate; the stored certificate lives in client attributes, read via `CertificateInfoHelper.getCertificateFromClient(client, prefix)` (`services/src/main/java/org/keycloak/services/util/CertificateInfoHelper.java`, attribute key `certificate`). Do not reuse the `x509.subjectdn`/`x509.casubjectdn` attributes.

Two recent commits show the complete set of touch points for adding a client authenticator: `FederatedJWTClientAuthenticator` ("federated-jwt") and `AttestationBasedClientAuthenticator` ("attestation-based") — Profile feature, `AbstractClientAuthenticator`, `OIDCLoginProtocol`, `OIDCWellKnownProvider`, service file, `DefaultAuthenticationFlows`, tests.

**Dependent changes**
1. New provider class + entry in `services/src/main/resources/META-INF/services/org.keycloak.authentication.ClientAuthenticatorFactory` (currently 6 entries).
2. New auth-method constant next to `OIDCLoginProtocol.TLS_CLIENT_AUTH` (line 129); return it from the factory's `getProtocolAuthenticatorMethods`. `OIDCWellKnownProvider.getClientAuthMethodsSupported()` then picks it up automatically for token/introspection/revocation metadata — no edit needed there.
3. Add an ALTERNATIVE execution in `DefaultAuthenticationFlows` client flow (`server-spi-private`, ~lines 470–522; priorities 5/10/20/30/40/50, some `Profile.isFeatureEnabled`-gated).
4. Add the new provider id to every `allowed-client-authenticators` list in `services/src/main/resources/keycloak-default-client-profiles.json` (7 occurrences) that already lists `client-x509`; check `SecureClientAuthenticatorExecutor`.

`DefaultClientValidationProvider` (~609) branches on `X509ClientAuthenticator.PROVIDER_ID`; admin-ui `clients/credentials/Credentials.tsx` and server-info mock JSONs mention `client-x509`. No `self_signed` literal exists yet anywhere.
